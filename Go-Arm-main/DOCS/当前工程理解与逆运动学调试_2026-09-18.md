# 当前工程理解与逆运动学调试

审阅对象：Go-Arm-main-main 当前目录，2026-09-18。以现有源码为准；旧 README、调试计划和代码复查部分结论已过时。本次没有修改固件控制代码。已直接编译运行原 kinematics.c 做主机数值验证，未进行整机固件编译、下载或真机测试。

## 1. 这个工程在做什么

这是 STM32H723 + FreeRTOS 的机械臂取放块控制工程，基于通用电控模板扩展。业务主线集中在 User/src/seize_sky.c，并不是 README 所展示的纯模板。

- 两台宇树 GO 电机控制平面两连杆机构，通过 UART7 / RS485 通信。上层 u1、u2 是已经折算到电机减速器输出侧、减去软件零点的弧度数，不是转子原始角度，也不是两个独立几何关节角。
- DJmotor[0] 是同步运动的第三轴，目标单位是度。代码没有把它纳入二维位置运动学；机械上它是否对应腕部及其传动关系，需要对照实物确认。
- PA9 由 Is_open 控制继电器。holding_jaw.c/h 基本为空，但不能据此说夹持控制完全没有实现：实际开关逻辑在 seize_sky.c。
- FDCAN3 接收整机命令，修改 Is_on、Is_ready、Is_pick、Is_place、level_flag 等。FDCAN2 对接 DJI 电机。不要沿用 README 中的旧总线说明。
- TIM2 中断调用 Arm_State_Update、UnitreeMotor_Func、DJmotor_Func；当前 DJI 调用已在每拍分支，并非旧说明的五分频分支。宇树轮询两台发送，每台发送频率不能直接当作定时器频率。
- Arm_Control_Task 每轮 osDelay(1)，更新诊断量、使能状态、动作状态并推进轨迹。它用固定 0.001 秒累计时间；实际任务延迟与执行开销未被测量补偿。
- 普通动作状态包括准备、天空块准备、底层/中层取块、各层放块、持块和回初始位。它们全部仍调用 Arm_Interpolation_Start，以预设电机角度运动。

控制链：外部 CAN 命令或调试状态 → 状态机 → 轨迹规划 → 电机位置设定 → 驱动协议 → 电机反馈。Forward 根据反馈估计末端位置；没有外部位置传感器闭环。

## 2. “两个坐标系”到底是什么意思

这里更准确的说法是“关节空间插值”和“笛卡尔空间插值”。它们不是世界坐标系/工具坐标系切换，也不是两套逆解公式。

关节空间用 u1、u2 描述电机转到哪里，笛卡尔空间用 x、y 描述末端在平面哪里。Inverse 是两种描述之间的转换。你队友增加的两种逆解调试模式，都输入同一个目标 x、y，但途中路线不同。

| 调试状态 | 当前枚举数值 | 修改的输入 | 中途如何走 |
|---|---:|---|---|
| ARM_DEBUG | 10 | Arm_Debug.u1_target / u2_target / dj_target / move_time | 直接对电机角度做插值；同时可观察正解 |
| ARM_Pos_DEBUG | 11 | Arm_Pos_Debug.x / y / dj_target / move_time | 仅开始时 Inverse 求一次目标角，再插值电机角 |
| ARM_CartPos_DEBUG | 12 | 同一个 Arm_Pos_Debug | 先插值 x、y，每拍 Inverse 求电机角 |

枚举数值只适用于当前版本，代码优先使用枚举名。

模式 11：目标坐标 → 一次逆解 → 目标电机角 → 电机角逐步变化。一般只能保证理论终点一致，末端途中通常走曲线。

模式 12：当前坐标到目标坐标的一条线段 → 每拍取线段上的点 → 每拍逆解 → 电机角。理想模型下末端沿直线走；速度由五次多项式决定，通常不是匀速。实际轨迹仍受跟踪误差、机构误差影响。

示例：当前位置为 (x0,y0)，只想向 +x 走 10 mm 并保持高度。模式 12 每拍目标都是 (x0+10s,y0)；模式 11 虽然终点也是 (x0+10,y0)，途中 y 一般会变化。

相关入口：seize_sky.c 的 Arm_Interpolation_Pos_Start、Arm_Interpolation_Cart_Start、Arm_Interpolation_Update。

## 3. 必须按“实际代码”理解的坐标定义

kinematics.h 当前参数：

```text
L1 = 389.5 mm
L2 = 423.42 mm
ZERO1 = 0 rad
ZERO2 = 2.3562 rad，约 135°
R = 2/3
```

kinematics.c 实际执行公式：

```text
theta1 = u1 + ZERO1
theta2 = ZERO2 - (u1 + u2) * R
x = L1*cos(theta1) + L2*cos(theta1 + theta2)
y = L1*sin(theta1) + L2*sin(theta1 + theta2)
```

theta1 是大臂相对 +x 的角度；theta2 是小臂相对大臂的有符号夹角；小臂相对 +x 的绝对角度是 theta1+theta2。数学上从 +x 朝 +y 为正转角。原点在模型的大臂转轴中心，末端是模型第二根杆的终点。代码没有基座平移、世界坐标变换或工具偏移补偿。

实际机身上 +x 究竟朝前还是朝后、+y 是否竖直向上，以及 L2 末端究竟是腕轴中心还是夹爪接触点，都要由机构与标定确认。仅凭变量名不能确定。

特别注意：文件顶部和 kinematics.h 仍写着 `(u1-u2)*R+ZERO2`，这是旧注释，与执行代码不一致。按照现有代码，保持 theta2 不变需要 du2=-du1，而不是两个电机增量相同。不要为了迁就旧注释把队友已经修改的公式改回去。

逆解取 theta2=acos(cos_theta2)，只取 [0,pi] 分支。所谓“肘部向上”取决于观察方向；可确认的事实是它选正 theta2。另一分支也可能到同一个 x、y，但电机角不同。跨分支、atan2 角度包络边界时不能假设目标角连续。

宇树驱动中的 6.33 是电机本体减速比；这里的 2/3 是外部机构的耦合传动系数，不能重复相乘。

## 4. 零点是明天首先要确认的事情

UnitreeMotor_Init 把每台电机 set_zero 置 true；UnitreeMotor_Func 在 data.correct 为真后调用内部 SetZero，记录 zero_offset 并把反馈/目标清为 0。反馈解析减去 zero_offset，命令发送加回 zero_offset。因此当前实际行为是“首次有效反馈后自动建立软件零点”，与 README 及头文件“不自动清零”的文字相反。

这意味着：当前模型要求建立零点时，实物大臂角约为 0°，肘部相对角约为 135°。若在另一个姿态重启，即使机械结构没有变化，x、y 计算也会改变。重启不是无副作用的调试操作。

DJI 驱动同样在第一次角度计算中执行软件清零。第三轴姿态也需要可重复基准。

明天先复现队友标定时的开机姿态，等待两台电机有效反馈及 set_zero 清除，验证读数，再做运动。不要在运动过程中重新清零。data.correct 仅表示最近记录的解析结果有效，不足以证明反馈没有过期；当前宇树驱动没有完善的反馈年龄门控。

## 5. “调每个位置的逆运动学参数”应该分成两件事

第一件是全局模型标定：杆长、初始几何角、符号、传动比例。这些参数描述同一台机械臂，不应每调一个点就改一遍。先用多个实测姿态验证 Forward 与物理坐标一致。

第二件是动作点位标定：READY、LOW、MID、HIGH 等每个动作的目标 x、y、第三轴角度、运动时间，以及过渡路径。模型验证通过后，你主要应调整这一层。

判断依据：

| 现象 | 先核查什么 |
|---|---|
| 多个姿态都有系统性的坐标偏差 | 零点、杆长、坐标轴方向、传动系数、工具参考点 |
| 只有某个动作抓不到，其他点的实测坐标正常 | 该动作的目标坐标、夹持姿态、动作时序 |
| 计算坐标正确，但电机实际角追不上命令 | 驱动增益、负载、速度、机械阻力与反馈；不要先改运动学 |
| 重启后同一套点位都失效 | 自动清零时的开机姿态是否变化 |
| 终点正确但途中碰撞或绕行 | 路径选择、过渡点、关节限位，不只是终点参数 |

看 Inverse(Forward(u))≈u，只能验证公式互相一致，不能证明杆长与真实机构一致。Arm_Kinetics_Data.end_coordinate 也是模型计算值，不能代替尺子、定位工装或其他独立实测。

## 7. 当前调试接口怎么用

这里的接口主要是 Keil Watch 中的全局变量和枚举状态；没有发现 CAN/串口接收任意 x、y 并选择这两个模式的完整协议入口。uvoptx 已保存 Arm_Pos_Debug、ArmControl 等 Watch 项。

建议观察：

```text
Is_on
ArmControl.state / last_state / running / finish / time / total_time
ArmControl.Cart
Arm_Debug
Arm_Pos_Debug
Unitree_motors[0].data.position / cmd.position / data.correct / data.error / set_zero
Unitree_motors[1].data.position / cmd.position / data.correct / data.error / set_zero
DJmotor[0].valNow.angle_deg / valSet.angle_deg
Arm_Kinetics_Data.arm_angle
Arm_Kinetics_Data.end_coordinate
```

Arm_Kinetics_Data.motor_target 实际拷贝的是 Arm_Debug，不代表逆解模式的真实目标；要看电机 cmd.position。Arm_Kinetics_Data.inverse_angle 是当前反馈正解再逆解的结果，也不是本次目标点的逆解值。

操作语义：

1. 先完成机械零点、反馈和当前位置命令对齐检查，隔离会自动发动作的上位机命令。失能时需有机械支撑，避免失去保持力后下落。
2. 三个调试模式都会控制 DJmotor[0]。只想试两连杆位置时，dj_target 要填已确认的当前第三轴角，不能放任默认 0。
3. 初次试逆解，把 Arm_Pos_Debug.x/y 填成经模型验证的当前点附近的小位移目标，move_time 填正数，例如初步用 5～10 秒观察小行程；这个时间不是速度安全保证。
4. 参数全部填写后，再将 ArmControl.state 改为 ARM_Pos_DEBUG 或 ARM_CartPos_DEBUG。状态变化会自动将 running/finish 都清为 false，Process 接着读取参数并开始轨迹；不需要手动置 running=true。
5. 同一调试状态完成后再次改参数，不会自动重跑。确认 running=false、finish=true，写完全部参数，最后把 finish=false，Process 才会再次启动。运动中不要用这套方式强行重启。
6. 不要通过切到 ARM_STATE_NONE 来“空闲一下”：它是返回 START 位姿的动作状态，不是无动作的空闲模式。不要改内部 Is_enable 代替 Is_on。

上述是当前代码的触发语义，不是完整上电安全流程。当前 Is_on=0 只阻止 Update，不阻止 Process 预先采集起点；失能后移动机构再使能可能沿旧起点继续。应先补充重新使能对齐和取消旧轨迹逻辑，再开展大范围调试。

旧《调试计划.md》中的“先使能、改 Is_enable、手动 running=true”不能作为本版的可靠操作指南。

VOFA 开关虽为 1，freertos.c 创建 VOFASendTask 的语句被注释，因此当前没有该任务输出。启用时需恢复任务创建并配置实际观测通道；现有任务仅更新宇树 0 的反馈角。另外 vofa.c 双缓冲维度写为 [VOFA_PACKET_SIZE][2]，索引却按两个整帧使用，且 busy 状态设置不完整，恢复高频输出前应修正这部分，不能只打开开关。

## 8. 明天前应优先处理的代码问题

这些结论来自本版代码，不是照搬旧复查报告。

1. **非法坐标会被逆解静默夹紧。** 两杆理论半径范围为 33.92～812.92 mm，尚不含限位和碰撞约束。Inverse 把超界 cos 值截到 [-1,1]，不返回错误。默认 Arm_Pos_Debug=(0,0) 不可达：模式 11 会生成另外一个位置的角度；模式 12 会在途中越界时停止更新并把 finish 标为 true。应改为有成功/失败返回值的逆解接口。
2. **直线路径没有启动前完整检查。** 两个端点可达，线段仍可能穿过中心不可达圆。现实现边走边检查，失败发生时可能已运动一段；最后一次直接写终点也没有统一经过检查。应启动前检查端点、整条路径、解分支及电机机械范围，再允许执行。
3. **没有明确的机械关节限位。** 宇树协议数值限幅不是机构限位；DJI 的 PosAngleLimitFlag 默认 false。限位必须来自实物测量，不能把理论可达环当作安全工作区。
4. **move_time 未统一校验。** Update 在任何分支前都调用 Quintic_Trajectory，除以 total_time；笛卡尔模式尤其直接使用结果。需要拒绝非正时间及 NaN/Inf 输入。
5. **finish 不是实际到位。** 它主要表示插值时间走完，也被用于不可达终止。应区分轨迹结束、实际到位和失败；到位需角度误差、反馈新鲜度及稳定持续时间等判据。当前 CAN 回传仅 level_flag，并未回传这些状态。
6. **零点/使能基准与反馈校验不完整。** 自动清零依赖开机姿态；使能前没有完整的双电机新鲜反馈、清零完成、错误状态检查。DJmotor_Monitor 调用被注释；宇树首拍对齐分支因 set_cur_init 初值 true 不会执行。
7. **五次曲线起始速度/加速度非零。** 当前 ARM_START_VELOCITY=0.8、ARM_START_ACCEL=4.6 是归一化量，并不是 rad/s 与 rad/s²。首轮从静止到静止的点位调试可先评估将两者都改为 0，使起止速度、加速度为 0；仍需合适的总时长，不等于具备限速和安全打断。
8. **逆解固定一个分支。** 从负 theta2 或不同角度包络的当前位置直接进入笛卡尔模式，第一拍 Inverse(Forward(now)) 就可能得到另一组角度。现有预设处于正分支，但手动移动后的姿态未必如此。

此外，旧文档提到的宇树反馈帧大小风险需要在目标 ARM 编译器下确认：本版已按字节解码，但接收 memcpy 和 CRC 长度仍依赖 sizeof(UnitreeMotorFeedbackFrame_t)，其中保留了混合类型位域。应验证接收结构大小为 16、发送为 17，并使用固定协议长度或静态断言；这次主机运动学验证不覆盖该驱动布局。

## 9. 怎样把调好的点正式接入动作

当前 seize_sky.h 的 ARM_U1_LOW_POS 等全部仍是电机角度。不要把 x、y 数字填进这些宏而继续调用 Arm_Interpolation_Start，否则会把毫米当弧度。

建议新增明确的动作点位结构与表，字段使用 x_mm、y_mm、dj_deg、move_time_s、path_mode。保留现有角度预设作为标定参考。调通一个动作后再替换它对应的 Process：

```c
/* 示意：这些字段需要先定义并填入真机标定值。 */
Arm_Interpolation_Pos_Start(low_pose.x_mm, low_pose.y_mm,
                            low_pose.dj_deg, low_pose.move_time_s);
/* 接近物块的短直线段，在完成整段检查后使用： */
Arm_Interpolation_Cart_Start(approach_pose.x_mm, approach_pose.y_mm,
                             approach_pose.dj_deg, approach_pose.move_time_s);
```

两段示意不是在同一个 Process 连续调用；那样后一次会覆盖前一次。多段动作要在状态机里分阶段等待实际到位后继续，或引入路径段队列。

先通过逆解关节插值确认目标点，再对需要直线接近/退出的短段使用笛卡尔插值。远距离切换需评估整条扫掠空间，必要时增加过渡点，不宜把所有现有动作直接替换成一条末端直线。

若目标是夹爪接触点且 DJ 控制腕部姿态，还需补充工具偏移与姿态模型；当前 Inverse 只解决二维两连杆位置，不会自动保持夹爪朝向。

## 10. 建议记录的调试数据

每个点记录：动作名、开机/清零姿态、目标 x/y、模型计算 x/y、独立实测 x/y、两宇树 cmd/data、第三轴 cmd/data、运动时长、路径模式、负载、是否干涉。只有目标和模型反馈两列，无法判断模型是否准确。

顺序：复现基准 → 验证反馈和角度正方向 → 多姿态正解与实测对比 → 当前点附近单点逆解 → 各动作终点标定 → 短距离直线 → 多段实际取放流程。静态终点通过之后再逐步缩短时间。

## 11. 本次离线验证与复现

运行 Tools/review_kinematics.ps1，使用本机 GCC 直接链接 User/src/kinematics.c。脚本从 seize_sky.h 提取启用中的预设宏，避免另写一份点位值。

- 当前 10 个预设的正解→逆解均回到原电机角，最大误差约 3.58e-7 rad。
- 正分支、远离奇异点及 atan2 包络边界的 10201 个样本：角度回代最大误差约 2.38e-6 rad，末端回代最大误差约 0.000220 mm，阈值检查全部通过。
