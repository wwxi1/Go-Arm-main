# 二维到位成功事件

用户确认约7 mm的反馈模型误差不影响抓取后，本次将二维位置容差设为10 mm，驻留200 ms，指令发完后最多等2 s。参数位于 `User/inc/arm_diag.h` 的 `ARM_DIAG_XY_*` 三个宏。

## 看到什么

正常顺序例如：

```
TrajectoryStart      state=1, duration_ms=5000
CommandsSent         state=1, result=2
XYArrivalSuccess     state=1, error_mm_rounded=7
```

`CommandsSent`是原0x3002事件的新显示名，表示五秒轨迹生成结束。若此时位置已合适，通常约再过210 ms出现一次Success（首次检查在下一次10 ms周期，之后保持200 ms）。它是额外的反馈验证事件，不改变 `ArmControl.finish` 或动作队列。

| 事件 | 意义 |
|---|---|
| `XYArrivalSuccess` | 已完成的动作，其两电机反馈算出的二维位置，在连续200 ms的检查中都处于10 mm内 |
| `XYArrivalTimeout` | 指令发完后2 s仍未满足条件；不是自动停机 |
| `XYArrivalAborted` | 等待到位期间被打断：reason=1新动作、2禁用、3动作取消/异常、4目标被另行修改 |

误差按mm四舍五入显示；超时时反馈无效或报错，误差显示-1。缺少有效新反馈时不能用旧角度判成功。新动作开始会结束旧动作的等待，事件中的state仍显示旧动作编号。

## 检查条件

- 指令已经发完，保存当时的最终目标；比较期间不跟随新目标移动。
- 机构仍使能；两台宇树通信新鲜且驱动错误码均为0。
- 每次检查两台反馈计数都更新，位置计算有限。
- 使用当前 `Forward()` 算法，欧氏距离平方不超过 `10*10 mm²`。
- 每10 ms检查，连续200 ms符合条件。任何一次超出、反馈失效或检查间隔超过20 ms，都重新计驻留时间，避免CPU暂停后直接“成功”。

这表示编码器和当前零位/几何模型估计的二维末端位置符合要求，不检查DJI姿态轴、夹爪是否真正抓住物体，也不独立验证上电机械零位。

## 下一次运行

1. 在允许重启的机械姿态下让机构安全停稳并禁用，退出调试。
2. F7编译、下载新程序，然后重新进入调试Run。既有软件置零行为仍要求按规定姿态上电。
3. 使用原来的 `MDK-ARM/ArmDiagnostics.scvd`；文件已更新，重新进入调试让Keil加载，无需添加第二份。
4. 打开Event Recorder并Enable，按原流程执行动作。指令发完后给它至少约0.21 s验证时间；提前启动新动作会记录Aborted。
5. 日常通信仍只需看 `g_arm_comm_ok`，到位结果直接看事件，不必新增一长串Watch变量。

仅换SCVD不能给旧固件增加验证逻辑，必须下载新构建。旧CSV里的Unverified记录也不会变成已验证结果。
