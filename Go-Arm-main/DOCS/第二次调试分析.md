## 事件记录

两次替换都是state4被state5替换，运行时间分别1.513 s和2.339 s；不能把这两次作为state4完成动作来判断到位。18次完成均记录5.000 s，这描述轨迹生成耗时，不证明物理到位。

## VOFA与末端坐标误差

CSV有63430行、6列，GBK编码，无空数值。通道顺序为目标0、反馈0、目标1、反馈1、力矩0、力矩1。没有每行主控时间戳及回包计数，不能据此重建每帧通信间隔。

按名义10 ms/行和多次动作变化对应，第一轮约有 `ER时间 = CSV行号*0.01 + 416.679 s`；第二轮约有 `ER时间 = CSV行号*0.01 - 23.54 s`。两段偏移不同，禁止强行使用全文件统一偏移推断时钟精度、长停顿原因或丢帧率。对应精度受10 ms采样和边缘识别限制。第一轮state1完成时刻早于CSV开头，但保留了后续保持位置的数据。

分别将每行的两个目标角和两个反馈角代入当前 `Forward()` 公式：

```
theta1 = u1
theta2 = 2.3562 - (u1+u2)*2/3
x = 389.5*cos(theta1) + 423.42*cos(theta1+theta2)
y = 389.5*sin(theta1) + 423.42*sin(theta1+theta2)
error_mm = sqrt((x_target-x_feedback)^2 + (y_target-y_feedback)^2)
```

## 到位判定建议

可以用电机反馈通过正运动学估计二维末端位置，再与保存的最终目标比较。应同时满足：两电机反馈新鲜、数值有限、零位基准有效、轨迹指令已发完、误差连续处于容差内（例如先评估200 ms驻留），有驱动器报错时不能宣称机构正常。驻留只是避免瞬间穿过，若要判断已经停稳还需速度条件。

当前测试所选窗口约0.3~7.0 mm，5 mm容差会使部分姿态不通过。容差应由实际抓取/装配要求决定，不能为了全绿而放宽。这里是编码器+几何模型估计，无法独立检测皮带打滑、连杆挠曲、夹具安装偏差和错误上电姿态。当前两电机模型只覆盖二维位置；末端姿态、DJI轴和夹取成功要另外判断。后续用户确认该偏差不影响抓取，已新增10 mm/200 ms的XYArrivalSuccess诊断事件，见[到位成功事件](到位成功事件.md)；本次原始CSV里的Unverified仍是历史未验证状态。

## 日常只看一个通信bool

新增 `g_arm_comm_ok`：两台宇树均收到过有效反馈，且最新反馈年龄都不超过阈值时为true；任意一台过期、从未收到、监测关闭均为false。它每10 ms检查一次，CPU不运行时这个软件状态也不会更新。

`g_diag_rx_timeout_ms` 默认改为10 ms。依据是已观察到典型间隔约2 ms，先给约5个回包周期的余量；这是调试候选阈值，并非从现有数据证明的极限，更不是安全保证。2~3 ms是正常样本的参考，不能直接拿P95是否等于2作为通信在线判断，因为断线后P95仍可保持2。

每台电机上线后，无论机械臂是否使能，都记录超时和恢复边沿；上电尚未接电机时bool为false但不刷超时。该状态只表示有效反馈新鲜，不表示驱动器无错误、零位正确或电机可安全运动。完全断线时，10 ms阈值加上最多一个正常检查周期意味着通常约10~20 ms反映到bool；任务延迟会再延后，不能作为硬实时保护出口。

第二次测试时的版本使用最近256个间隔的滑动窗口，P50/P95每秒重算。第四次测试后按实际使用需要删除了这部分统计；当前版本仅保留最近一次间隔、有效接收时间与计数，通信bool和超时/恢复事件不变。

下一次下载后，先在机构禁用且可靠支撑时看 `g_arm_comm_ok`。通信正常应为true；断开电机RS485链路应变false并记录FeedbackTimeout；恢复后变true并记录FeedbackRecovered。只用于诊断，不自动停机。随后在正常动作中观察是否误报，才决定是否调整候选阈值。
